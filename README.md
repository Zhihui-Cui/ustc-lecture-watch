# USTC Lecture Watch

中国科学技术大学研究生系统「学术报告选课」新增报告监控工具。

在官方浏览器页面手动登录后，程序每分钟读取当前筛选范围的全部未选报告。首次记录已有报告，之后发现新编号且允许选课时，使用自己的登录状态提交选课请求。

**本地版本已在 Windows + Python 3.12 环境完成真实列表查询和持续轮询验证。自动提交最终以学校后台返回为准，不保证名额，也不提供绕过容量或资格限制的功能。服务器和邮件通知仅作为[拓展思路](docs/cloud-extension.md)，不属于本仓库已验证的运行方式。**

本项目是个人工具，与学校官方无隶属关系。请使用自己的账号，遵守学校选课要求，并实际参加成功报名的报告。

## 功能与边界

- 通过官方页面手动登录，无需在源码中填写学号和密码。
- 每轮直接向后台查询，不依赖网页是否手动刷新。
- 支持院系等页面筛选，遍历全部分页并按 `BGBM` 去重。
- 记录已有编号和处理结果，重启后继续监控。
- 新报告尚未开放选课时继续等待；`SFKXK == 1` 时尝试提交。
- 仅后台业务响应 `code == 0` 才标记成功，HTTP 200 本身不代表选课成功。
- 后台明确拒绝后不自动重复提交该报告；提交结果不明时暂停该报告的处理。
- 提供只检查、不提交的 `--dry-run` 模式。

**默认会处理监控范围内所有符合条件的新增报告，没有额外的主题、时间冲突或报名数量筛选。启动前请设置合适的范围。**

## 环境

- 已实测：Windows、Python 3.12、Edge/Chrome。
- 依赖：`playwright==1.64.1`。
- 本地运行需要图形桌面，能够打开浏览器并访问学校研究生系统。
- macOS/Linux 桌面环境可自行尝试；本仓库没有这些平台的学校端实测记录。SSH 无桌面服务器不能直接照搬本地运行流程。

## 快速开始：Windows

### 1. 获取代码

```powershell
git clone https://github.com/Zhihui-Cui/ustc-lecture-watch.git
cd ustc-lecture-watch
```

也可以从仓库首页选择 **Code → Download ZIP**，解压后在该目录打开终端。

### 2. 安装依赖

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

程序优先尝试已安装的 Edge、Chrome。如果都没有，可以安装 Chromium：

```powershell
.\.venv\Scripts\python.exe -m playwright install chromium
```

直接使用虚拟环境中的 Python 不需要运行 PowerShell 激活脚本。

### 3. 先检查运行环境

```powershell
.\.venv\Scripts\python.exe lecture_watch.py --dry-run
```

在新打开的浏览器中：

1. 完成学校统一身份认证。
2. 进入「学术报告选课」，打开未选报告列表。
3. 设置要监控的院系等筛选；如果希望查看全部则清空筛选。
4. 回到终端按回车。

看到「后台读取完成」和「基线已建立」后，说明列表查询已经跑通。检查模式不会提交选课，也不改变正式状态文件。按 `Ctrl+C` 退出。

### 4. 开始自动监控与选课

```powershell
.\.venv\Scripts\python.exe lecture_watch.py
```

重新在弹出的浏览器中登录、设置相同的筛选范围，回终端按回车。**这次会对后续符合条件的新增报告实际提交选课请求。**

第一次成功查询建立正式基线；已经存在的报告不会自动报名。以后每轮会显示报告总数、新增数和可提交数。成功后应到学校「已选报告」页面核实。

保持程序、浏览器和网络运行，电脑不要睡眠或休眠。单纯关闭显示器不等于睡眠。浏览器页面休眠或登录失效也可能影响监控。

### Linux/macOS 桌面环境参考

以下命令使用 Bash，与 Windows PowerShell 的路径写法不同；平台行为需自行验证。

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m playwright install chromium
.venv/bin/python lecture_watch.py --dry-run
```

## 「新增」和「可提交」具体是什么意思？

| 情况 | 行为 |
| --- | --- |
| 第一次正式运行就存在的报告 | 写入基线，不自动报名 |
| 后续首次出现的新 `BGBM`，且允许选课 | 提交一次 |
| 新发现的报告暂未开放，后来允许选课 | 继续等待，开放后尝试提交 |
| 旧报告后来有人退选、产生余位 | 不处理；本项目不是旧报告余位捡漏工具 |
| 当前院系筛选排除的报告 | 不检查 |
| 后台明确拒绝 | 保存原因，不继续重复提交 |
| 提交超时或中断，结果不明 | 标为待人工核实，避免重复报名 |

「可提交」是新发现、尚待处理且当前允许选课的报告数，不是整个列表中有余位的数量。

程序目标是每 60 秒开始一轮，**每轮可能发出多个分页请求**。网络慢或报告较多时一轮会超过一分钟；程序不会并发启动重叠轮次。

开始监控后请保持筛选范围固定。扩大范围或手动退选可能使以前未记录的旧报告进入列表，被当作新出现。若要改变监控范围，先停止程序并重新确认基线。

## 状态文件、停止和重启

脚本旁边自动生成：

- `lecture_watch_state.json`：已见编号、新报告及处理状态；不包含账号密码或 Cookie，但可能包含个人选课记录，应保密。
- `lecture_watch_state.lock`：单实例锁文件；正常退出后锁自动释放，文件仍可能保留。

在终端按 `Ctrl+C` 停止。再次运行需要重新在浏览器登录，监控记录会沿用。

升级程序时保留状态文件。迁移到另一个目录时，可在两个程序都停止后复制该文件。不要同时在多个目录启动同一账号的自动选课实例；单实例锁只保护同一路径。

检查模式采用临时内存基线，退出即丢弃。删除正式状态文件会重建基线，不会立即自动报名全部旧报告。不同学校账号应使用不同目录和状态文件。

## 常见问题

**页面没有刷新，能发现新报告吗？**

能。程序重新请求后台列表，并使用返回的编号提交，网页画面不一定同步变化。

**「入口加载未完成」怎么办？**

在已打开的浏览器中完成加载或刷新、登录并进入列表，再回终端按回车。能继续出现「已识别列表查询」说明后续步骤已执行。

**「本轮未完成查询，不提交选课」意味着什么？**

该轮没有进入选课处理。检查网络、登录状态、筛选范围和错误文字。分页不完整或后台页码未生效时，程序不会把部分结果当作完整列表。

**登录过期、浏览器关闭了怎么办？**

本地版不会自动填写密码或处理验证码。恢复浏览器登录和未选报告页面；无法恢复时停止后重启，保留状态文件。

**提示容量已满，为什么不继续提交？**

容量由后台检查，直接调用接口不保证能选上。程序记录拒绝原因，不持续重试该报告。

**`No module named playwright` 或找不到浏览器？**

确认安装依赖和运行程序使用同一个 Python；按上面的虚拟环境命令安装依赖和 Chromium。

## 开发与测试

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

仓库包含 14 项离线逻辑测试，覆盖分页、去重、基线、重启、状态冲突和单实例锁。测试不会登录学校或实际报名；离线通过不等于学校端接口永远不变。

当前实现依赖学校页面提供的查询结构和选课模块，系统升级后可能需要适配。提交 Issue 时请提供 Python/系统版本、脱敏错误文字和复现步骤，不要上传 Cookie、授权码、HAR 抓包文件、学号、运行状态文件或学校完整响应。
